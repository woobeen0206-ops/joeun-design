# 결정 기록

## 2026-09-11 — Codex로 개발 환경 전환

- 공통 지침은 `AGENTS.md`, 설정은 `.codex/config.toml`로 통일한다.
- FE/BE 에이전트는 `.codex/agents/frontend-dev.toml`, `.codex/agents/backend-dev.toml`을 사용한다.
- 설계 문서는 `.codex/docs/`, 향후 스킬은 `.agents/skills/`에 둔다.
- 중복된 이전 도구 설정과 내용이 없는 스킬 파일은 제거한다.
- 모델과 실행 권한은 사용자/앱 설정을 유지한다.
- 기존 Next.js + Spring Boot + PostgreSQL 및 단일 서버 계획은 유지한다. 애플리케이션 구현은 아직 시작하지 않았다.

## 2026-10-11 — 정적 홈페이지 원본과 AWS 배포 흐름 표준화

- 현재 운영 홈페이지의 유일한 원본은 `frontend/public/cases/`다.
- `design-preview/`는 과거 시안과 검토 자료 보관용이며 운영 배포에서 제외한다.
- 현재 공개 사이트는 S3 버킷 `joeun-design`과 CloudFront 배포 `E331KD2S9HFPJA`를 사용한다.
- 운영 배포 경계는 자동 생성되는 `.deploy/site/`로 고정한다. 원본 폴더나 프로젝트 전체를 S3에 직접 올리지 않는다.
- `.deploy/site/`에는 HTML에서 실제 참조하는 파일만 수집하고, 파일별 해시는 `.deploy/deploy-manifest.json`에 기록한다.
- `올려.command`는 원본 검사 → 배포 산출물 생성 → 빌드·린트 → S3 변경 파일 업로드 → CloudFront 캐시 무효화 → 공개 파일 일치 확인을 순서대로 실행한다.
- 자동 배포는 S3 객체를 삭제하지 않는다. 삭제와 버킷 버전 관리는 비용·복구 정책을 정한 뒤 별도로 적용한다.
- 관리자와 백엔드가 구현되기 전까지 공개 포트폴리오는 이 정적 배포 구조를 사용한다.

## 2026-10-11 — GitHub 릴리스를 운영 배포의 필수 게이트로 사용

- 운영 배포 전 현재 변경사항을 루트 Git 저장소의 `main`에 커밋하고 GitHub `origin`으로 푸시한다.
- 릴리스 태그는 서울 날짜 기준 `vYYYYMMDD.0.N` 형식을 사용하며 같은 날 재배포할 때 마지막 번호를 올린다.
- 커밋과 태그가 GitHub에 올라간 뒤에만 S3·CloudFront 배포를 시작한다.
- AWS 배포가 실패하면 이번 실행에서 만든 태그만 로컬과 GitHub에서 삭제한다. 커밋은 수정과 재시도를 위해 유지한다.
- 과거 중첩 Git 구조는 제거하고 `frontend/`를 루트 저장소가 직접 관리한다.

## 2026-10-11 — 새 대화의 프로젝트 진입점을 스킬로 고정

- 새 대화에서도 이전 채팅 기억 없이 현재 저장소를 읽고 작업할 수 있도록 `joeun-design-project-guide` 스킬을 사용한다.
- 이 스킬은 원본 위치, 수정 금지 구역, 사진·영상 처리, 견적 화면, 검증과 배포 라우팅을 안내한다.
- 실제 운영 배포는 프로젝트 가이드가 직접 수행하지 않고 `deploy-joeun-site` 스킬로 연결한다.
